# Deploying mickys.in (Next.js app in `web/`)

## What changed
| | Before | After |
|---|---|---|
| Root `vercel.json` | `@vercel/static-build` of `frontend/package.json` (the old Vite app), serving `frontend/dist` | `@vercel/next` of `web/package.json` (this Next.js app) |
| Old apps | deployed | untouched on disk (`frontend/`, `admin/`, `backend/`, `legacy-static/`), no longer deployed |

## Recommended Vercel project settings
Configure the project to build this folder directly (this is what Vercel recommends for a Next.js app in a subfolder):

- **Root Directory:** `web`
- **Framework Preset:** Next.js
- **Install Command:** `npm install` (default)
- **Build Command:** `next build` (default, `npm run build`)
- **Output Directory:** leave empty (Next.js default `.next`)
- **Node.js version:** 20.x or newer

When Root Directory is `web`, the root `vercel.json` is not used. It only makes a deploy from the repository root build the same app.
Note: `web/` is its own git repository. If the Vercel project is connected to that repository, its root already is this app, and no Root Directory setting is needed.

## Environment variables (Project Settings → Environment Variables)
Names only; see `.env.example`. Never add a secret with a `NEXT_PUBLIC_` prefix.

| Variable | Exposed to browser | Notes |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | yes | `https://mickys.in` (canonical URLs, sitemap, OpenGraph) |
| `NEXT_PUBLIC_RAZORPAY_KEY_ID` | yes | Key ID only |
| `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, `RAZORPAY_WEBHOOK_SECRET` | **no** | server only; test keys until the full flow passes |
| `RAZORPAY_ALLOW_LIVE` | no | `false` until approved |
| `B2B_LEADS_WEBHOOK_URL/_TOKEN`, `CONTACT_WEBHOOK_URL/_TOKEN` | no | where enquiries are delivered |

## Before the first production deploy
- Payments stay unavailable in production until the order store (WooCommerce) is connected; this is intentional.
- Policy pages are live routes that say "being finalised" (noindex) until approved text is added in `data/legal.ts`.

# Backend on Render (`backend/`)

The Express API in `../backend` (MongoDB, orders, Razorpay, Shiprocket, email, admin) is set up for Render
with the Blueprint file **`../render.yaml`** at the project root.

**Important:** the new Next.js site in `web/` does **not** call this backend. Its cart, checkout,
Razorpay and form handling run as its own API routes on Vercel. Deploy the Render backend only if
the admin app / Shiprocket / Mongo order flow is still wanted, or once `web/` is wired to it.

## Render settings (from `render.yaml`)
| Setting | Value |
|---|---|
| Service type | Web Service (Node) |
| Root directory | `backend` |
| Build command | `npm ci` |
| Start command | `npm start` (`node server.js`, listens on Render's `PORT`) |
| Health check | `/api/health` |
| Node | 20 (also pinned in `backend/package.json` engines) |
| Region | Singapore |
| Auto-deploy | off (deploy manually until approved) |

## Steps
1. Put the project in a Git repository that contains both `web/` and `backend/` (today only `web/` is a repo).
2. Render Dashboard → **New + → Blueprint** → choose the repo → Render reads `render.yaml`.
3. Enter the secret values Render asks for (all `sync: false` keys). `JWT_SECRET` is generated by Render.
4. Set `FRONTEND_URL` to the Vercel site URL (e.g. `https://mickys.in`) so CORS allows it.
5. Deploy, then open `https://<service>.onrender.com/api/health` → `{"status":"OK"}`.
